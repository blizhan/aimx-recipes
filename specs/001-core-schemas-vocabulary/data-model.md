# Data Model: Core Schemas & Facet Vocabulary

Status: implemented contract version `2.0.0`, a breaking correction of the unreleased `1.0.0` draft. See `schemas/2.0.0/release.json` for compatibility and regeneration decisions. The eight entities are immutable observations/artifacts from the validator's perspective; there are no persisted lifecycle transitions.

## Common conventions

- All entity objects require `schema_version` (exactly `2.0.0`) and `entity_type` (one of `source`, `document`, `problem`, `problem_profile`, `recipe`, `attempt`, `evidence`, `experiment_proposal`). Each has the entity-specific ID below.
- IDs are nonempty, whitespace-free strings matching `[A-Za-z0-9][A-Za-z0-9._:/-]*`, opaque to consumers and unique within entity type. IDs are supplied, not generated by validation. Cross-type equality is allowed; references are typed by field.
- Fields below are required unless marked optional. Nullable means explicitly accepting null; it does not imply optional. Objects reject extra fields except named free-form metadata objects.
- Text is a non-whitespace string unless explicitly a document body or verbatim quote. No trimming or normalization occurs. Arrays preserve order; reference arrays and declared sets reject duplicates.
- Integers are exact non-boolean integers; numbers are finite non-boolean numbers. SHA-256 fields are 64 lowercase hexadecimal characters. Timestamps are RFC 3339 with timezone; dates are ISO calendar dates.
- Shared free-form configuration/extension objects permit JSON-domain values, but are not evaluated, merged into authoritative fields, or treated as evidence.

## Source

Required: `source_id`, `kind`, `canonical_ref`, `license`, `snapshot_id`, `content_sha256`.

`kind`: `writeup`, `competition_page`, `forum_post`, `notebook`, `paper`, `repository`, `openml_run`, `local_result`, `synthetic`. These are identity categories, not adapter promises. `canonical_ref` is a nonempty original URL or external identifier. `license` is `{status, identifier, attribution}`: status `permissive|restricted|unknown`, identifier and attribution nullable strings. A permissive or restricted classification requires a nonnull identifier. Optional `published_at` is a nullable timestamp; optional `mirrors` is a unique list of reference strings.

Snapshot identity and raw-artifact hash identify the original source snapshot. They are not assumed equal to normalized Document hashes. No runtime permission is inferred from structural validity or the `permissive` label.

## Document

Required: `document_id`, `source_id`, `snapshot_id`, `section`, `content_sha256`, `normalization_version`. `section` is a nonempty identifier such as `body` or `evaluation`; `normalization_version` identifies the producer's normalization policy. Optional `title` is nullable text.

The normalized text is passed separately in validation context and is never a Document field. Its hash is SHA-256 of its UTF-8 bytes, without further normalization. `snapshot_id` must equal the referenced Source snapshot. One Source can own many Documents. A content change requires a new document identity/version from the producer; validation does not rewrite it.

## Problem

Required: `problem_id`, `kind` (`competition|benchmark_case|caller_task`), `title`, `source_ids` (possibly empty for synthetic/caller tasks). Optional `description` is text; optional `as_of` is a timestamp or null. Source IDs must resolve when a complete bundle is supplied. `as_of` supports downstream temporal evaluation; no corpus filtering happens here.

## Problem Profile

Required: `profile_id`, `problem_id`, `vocabulary_version`, `facets`, `hard_constraints` (possibly empty list of conditions). A profile references one Problem; multiple explicitly identified versions may coexist. `facets` maps declared dotted facet names to assertions; absent keys mean unknown.

An assertion is `{value, basis, source?, confidence?, conflicts?}`. Basis is `observed|reported|inferred|unknown`. Known assertions require a nonnull vocabulary-valid value; unknown assertions require null. Optional `source` is `{kind: document|caller|annotation, ref: string}`; document references resolve contextually. Confidence is `low|medium|high` if supplied. Conflicts are a list of assertions with the same shape except that nested `conflicts` is forbidden. Preserve entries and their available provenance even when they agree. Different known values or nonempty conflicts do not silently select a winner.

Facet values and condition operators are fixed in [vocabulary.md](contracts/vocabulary.md).

## Recipe

Required: `recipe_id`, `canonical_name`, `aliases` (unique text array, may be empty), `vocabulary_version`, `taxonomy_version`, `action_type`, `action`, `description`, `applicability`, `preconditions`, `hard_constraints`, `contraindications`, `configuration`, `implementation_refs`, `expected_effect`, `cost_profile`.

`applicability`, `preconditions`, and `hard_constraints` are lists of vocabulary conditions. Each list may be empty; free-text applicability is rejected. Contraindications and expected effects are text arrays; implementation references are reference strings without fetching. Configuration is a free-form JSON object. `cost_profile` is `{implementation, compute}` with each value `low|medium|high|unknown`. Neither cost implies a numeric execution budget. No `support`, `adoption`, `counterevidence` or generic authoritative evidence field is accepted.

A condition is `{condition_id, facet, op, operand}` with optional `description`. IDs are unique within the owning record across all condition lists. The same vocabulary governs conditions and profiles. Canonical required conditions are named `preconditions`; `requires` is not an alias accepted by the contract.

## Attempt

Required: `attempt_id`, `problem_id`, `document_id`, `recipe_id` (string or null), `raw_method_name`, `baseline_method` (text or null), `candidate_method`, `configuration` (JSON object), `validation_protocol` (text or null), `evaluation_scope` (enum or null), `metric_name` (vocabulary metric or null), `metric_direction` (`minimize|maximize` or null), `baseline_value`, `candidate_value`, `reported_delta` (each finite number or null), `joint_change` (boolean), `joint_changes` (text array), `outcome`, `confounders` (text array), `provenance`.

Scopes: `cv|public_lb|private_lb|holdout`. Outcomes: `positive|negative|neutral|mixed|unclear`. Any nonnull numeric result requires scope, metric, and direction. No sign constraint applies generally to measurements; metric-specific domains are explicit vocabulary metadata. Optional `metric_k` is an exact positive integer or null; it is required nonnull for `map_at_k` and must otherwise be null/absent. Metric direction and measurement domains follow the vocabulary; reported deltas may have either sign. No delta is calculated or reconciled automatically. `joint_change=true` requires nonempty joint_changes and confounders; false requires empty joint_changes. Unknown confounding can be described explicitly without inventing causal certainty.

Each Attempt must have at least one Evidence in a complete bundle. Null recipe means unmapped; otherwise the Recipe must resolve. References to different evaluation scopes require separate Attempts, not unlabeled combined measurements.

## Evidence

Required: `evidence_id`, `attempt_id`, `document_id`, `type`, `outcome`, `quote`, `char_start`, `char_end`, `uncertainty` (text array), `comparison` (object or null), `provenance`.

Types: `controlled_ablation|reported_gain|reported_failure|used_in_solution|attempted|author_opinion|independently_reproduced`. Outcome uses the Attempt enum independently of type. `comparison` is `{baseline, candidate}` with nonempty strings and is required nonnull for controlled ablations. Both strings must occur verbatim within the quote. This checks a declared comparison's anchors, not its scientific validity. Independent reproduction remains a reviewable annotation; validators do not infer independence from counts.

The Evidence document must match the Attempt document. A span uses zero-based Unicode code-point positions, inclusive start and exclusive end. Require `0 <= start < end`, `end-start == len(quote)`, and quote length 1–500. With context text require `end <= len(text)` and `text[start:end] == quote`. Never search for alternate occurrences or normalize. Document content hash must match supplied text. Attempts and their evidence must trace through a Document to its Source.

## Provenance (shared value object)

All provenance contains `origin` and `source_content_sha256` (Document hash).

- `origin=extracted`: require `provider`, `requested_model`, `served_model`, `prompt_version`, `prompt_hash`, `schema_version`, `extractor_version`, `extracted_at`; all nonempty with hash/time/version rules. `requested_model` may name a gateway group. Optional `fallback_served` is a boolean supplied by the extractor; do not infer fallback from a group name.
- `origin=human`: require `author_ref`, `authored_at`; model fields forbidden.
- `origin=synthetic`: require `fixture_id`; model fields forbidden.

Context checks compare the provenance fingerprint to the referenced Document. The provenance schema version must match the containing record for extracted records. No source-document content is copied into provenance.

## Experiment Proposal

Required: `proposal_id`, `profile_id`, `recipe_id`, `evidence_ids` (nonempty unique list), `review_status` (constant `requires_lead_review`), `match`, `experiment_contract`. Detailed nullability and upstream correspondence are in [proposal.md](contracts/proposal.md).

`match` is `{level, transfer_risk, assessments}`. Levels `L1|L2|L3|L4` have the meanings in FR-013; risks are `low|medium|high|unknown`. Each assessment is `{owner_type: recipe|problem_profile, owner_id, condition_id, facet, state: satisfied|violated|unknown, reason}`. Supplied assessments must reference actual conditions of this proposal's recipe/profile, with matching facet and unique owner/condition identity. Every hard constraint of those owners must have exactly one assessment; omissions in complete context are invalid. The owning condition determines whether it is hard. Conflicting/unknown profile facets cannot be asserted satisfied. No scores or execution eligibility are computed. Violated conditions may be represented for review and cannot be relabeled satisfied; a structurally valid rejected candidate is not endorsed.

## Validation boundaries and transitions

No entity is automatically enriched, migrated, admitted, or persisted. A validation operation progresses through JSON-domain checks, version selection, structural checks, then requested contextual checks. Errors dominate missing-context diagnostics: final status is invalid if any error exists, otherwise incomplete if any required check is unavailable, otherwise valid at the explicitly reported level. Structural validity alone never means contextual completeness or execution readiness.

The release manifest and exact supported-version registry define permissible interpretations. See [validation-library.md](contracts/validation-library.md) for results and [quickstart.md](quickstart.md) for acceptance scenarios.

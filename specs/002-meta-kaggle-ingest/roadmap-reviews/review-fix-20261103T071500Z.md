## 逐项修复对照与证据

### 1. S-01 (major) — 临时文件越过 raw 写入边界
- **审查问题**：`write_table_parquet` 和 `evaluate_and_write_membership` 使用系统 `tempfile.NamedTemporaryFile`，正文和中间数据落盘在 `/tmp`；DuckDB 会话未设 raw 内 spill 目录。
- **改动**：
  - `src/aimx_recipes/sources/kaggle/snapshot.py`：`write_table_parquet` 改为在目标输出文件同级目录（即 staging tmp 目录 `out_path.parent`）创建临时 NDJSON，在 `finally` 块中删除。
  - `write_snapshot` 中创建 staging 内的 `spill_dir = tmp_dir / ".duckdb_temp"` 并传入 `open_session(..., temp_dir=spill_dir)`，发布前清理。
  - `src/aimx_recipes/sources/kaggle/membership.py`：中间 NDJSON 与 DuckDB 会话 spill 同样放置在 `tmp_mem` 内并在发布前清理。
- **验证证据**：
  - 探针 `temporary_files`: `outside_raw=true, paths=[]`，捕获到的系统 `tempfile.NamedTemporaryFile` 文件数为 0。
  - 单测 `tests/contract/test_cli_ingest_contract.py::test_no_writes_outside_data_dir` 拦截系统临时文件并断言 0 外部写入。

### 2. S-02 (major) — 把未知日期/metric direction 伪装成已知值
- **审查问题**：缺失 `PostDate` 或 `EnabledDate` 时被填充为 `"1970-01-01T00:00:00Z"`；缺失 `EvaluationAlgorithmIsMax` 被硬编码转为 `False`。
- **改动**：
  - `src/aimx_recipes/sources/kaggle/normalize.py`：
    - `build_writeup_source` 和 `build_competition_source`：若日期为 `None`，`published_at` 保持 `None`（001 Schema 支持 `"published_at": ["string", "null"]`）。
    - `normalize_competition_row`：`eval_is_max` 为空时 `higher_is_better` 为 `None`；非空时仅严格解析 boolean，非法非空值抛出 `DateParseError`。
- **验证证据**：
  - 探针 `missing_values`: `published_at: null`, `higher_is_better: null`。
  - 单测 `tests/unit/kaggle/test_records.py`（缺失日期生成 valid 的 Source 且 published_at 为 None）；`tests/unit/kaggle/test_resolve.py::test_missing_and_invalid_metric_direction_and_date`。

### 3. S-03 (major) — 解析错误回显输入内容，缺少定位字段

- **改动**：
  - `src/aimx_recipes/sources/kaggle/normalize.py`：`DateParseError` 改造为携带 `file`, `line`, `record_id`, `column`，消息使用固定脱敏格式，严禁拼接原始日期字符串。
  - `src/aimx_recipes/cli/__init__.py`：CLI 统一异常处理增加脱敏保护，避免透传可能包含正文的多行文本。
- **验证证据**：

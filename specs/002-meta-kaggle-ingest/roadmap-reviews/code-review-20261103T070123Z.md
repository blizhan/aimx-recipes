## Standards

### S-01 — major / open：读取和复用阶段仍可在 raw 外 spill

**证据路径**：`src/aimx_recipes/sources/kaggle/__init__.py:124`、`:152`；`membership.py:506`；`snapshot.py:244` 的 `open_session`；本轮 JSONL `actual_ingest_session_settings`、`default_session_synthetic_spill`。

实际首跑和重跑捕获 5 个会话，其中 3 个未指定 temp_dir，DuckDB 返回 `temp_directory = .tmp`，相对于 cwd。合成大排序使用同一 `open_session`、32MB 内存，实际在隔离 cwd 的 `.tmp/` 写入 **46,301,184 bytes**，不在 data/raw 中。该 probe 是会话能力复现，**不是声称参考 ingest 已实测发生正文 spill**；但生产读取路径确实使用同样设置，无法满足 Constitution Operational Boundaries、FR-001/FR-016 的无条件边界。

旧 `temporary_files` 的 `paths=[]` 仅说明没有调用 NamedTemporaryFile。`outside_raw=true` 是 `all([])` 的空集结果，既不能证明外写，也不能证明无外写。现有 `test_no_writes_outside_data_dir` 仍无法捕获 DuckDB 的 native 文件创建。

**建议验收**：所有 ingest/verify 会话都显式限定 raw 内临时目录或禁用 spill；正常/异常均清理；以能观察 native 写入的验证覆盖低内存路径。

### S-03 — major / open：通用异常截断不等于脱敏，稳定错误码仍缺失

**证据路径**：`src/aimx_recipes/cli/__init__.py:137`；`src/aimx_recipes/sources/kaggle/resolve.py:44`；本轮 JSONL `numeric_diagnostic`、`membership_write_failure`。

只把 mini fixture 首条 Teams 的 CompetitionId 改成合成 `PRIVATE_BODY_MARKER`，实际 CLI exit 1，输出 `invalid literal for int() with base 10: 'PRIVATE_BODY_MARKER'`，code=`runtime_error`，无文件/行/id/列。只取首行最多 120 字符仍泄漏输入正文片段，违反 CLI contract 的 messages never embed source rows/body。日期特例修复不足以关闭原问题。

另以 membership 写入 OSError 注入验证回滚：虽清除了新 snapshot，错误仍为 `runtime_error`，未映射合同 `write_failed`。带 code 的异常还直接透传原文；本轮损坏 parquet 输出包含底层 DuckDB SQL 文本。

**建议验收**：在数值/关系解析边界生成固定说明和可信定位；底层错误不直接展示；文件写失败映射 write_failed；分别覆盖 JSON、text/stderr。

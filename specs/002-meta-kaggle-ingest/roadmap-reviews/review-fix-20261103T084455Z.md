### 1. S-03 (minor) — 底层写入异常与关联后 message_id 错误分类
- **审查问题**：
  1. `ForumMessages.Id` 与 `ForumTopics.FirstForumMessageId` 为相同非法非数字字符串时，SQL `LEFT JOIN` 仍可匹配，但在 `normalize.py:253` 执行裸 `int()` 时抛出未捕获的 `ValueError`，导致退化为无文件/列定位的 `runtime_error`。
  2. 原生 DuckDB COPY 写操作失败（例如目标路径为同名目录或磁盘满）时抛出 `duckdb.IOException`，CLI 顶层仅捕获 Python 原生 `OSError`，未能映射为合同约定的 `write_failed`。
- **改动代码**：
  - `src/aimx_recipes/sources/kaggle/resolve.py`：
    - 在解析 `first_message_id` 与 `fm_id` 时调用 `safe_int`，如果值非法则精准抛出 `InputError`，分别定位至 `ForumTopics.csv:FirstForumMessageId` 与 `ForumMessages.csv:Id`，杜绝非法数字进入下游规范化阶段。
  - `src/aimx_recipes/sources/kaggle/normalize.py`：
    - `normalize_writeup_row` 中的 `msg_id_val` 增加防御性 `try...except (ValueError, TypeError)` 保护，在异常时抛出规范的 `ERR_CSV_MALFORMED` 错误，携带精确的字段名和 `topic_id`。
  - `src/aimx_recipes/cli/__init__.py`：
    - 顶层引入 `import duckdb`，将底层写异常捕获扩大为 `except (OSError, duckdb.IOException):`，统一脱敏映射为 `code: ERR_WRITE_FAILED`（`"write_failed"`），消息固定为 `"File operation or disk write failed"`。
- **验证证据**：
  - 探针 `malformed_message_id`：`exit: 1`，`errors: [{"code": "csv_malformed", "column": "FirstForumMessageId", "file": "ForumTopics.csv", "message": "Invalid integer in column 'FirstForumMessageId' of 'ForumTopics.csv'", "record_id": "1001"}]`，`marker_leaked: false`。
  - 探针 `native_duckdb_write_failure`：`exit: 1`，`errors: [{"code": "write_failed", "message": "File operation or disk write failed"}]`，`remaining_manifests: 0`。

### 2. F-01 (major) — 快照与 Membership 复用时缺少语义与字段类型校验
- **审查问题**：
  1. `verify_existing_membership` 仅核对键名是否存在，不核对字段值与类型。篡改 `membership_details` 中的 `membership_id`、虚假标为 `status: final`（即便实际含有 unreviewed 候选）、非字典的 `p0_in`/`p0_out` 或负数计数均被放行并复用。
  2. `verify_existing_snapshot` 未核验 manifest 中的 `snapshot_id` 是否与当前期望的 `snapshot_id` 匹配，也未比对记录的 `counts` 与实际 parquet/jsonl 行数。
  3. `outputs` 列表中若含有非字典项时抛出未分类异常而不是 `snapshot_conflict`。
- **改动代码**：
  - `src/aimx_recipes/sources/kaggle/membership.py`：
    - 遍历 `outputs` 时严格断言每一项为 dict 且包含合法 string `path`，否则抛出 `SnapshotConflictError`。
    - 校验 `membership_details["membership_id"]` 必须与 `expected_membership_id` 及顶层 `manifest["membership_id"]` 完全一致。
    - 校验 `details_raw["status"]` 必须为 `"final"` 或 `"provisional"`，且与顶层 `manifest["p0_status"]` 完全匹配。
    - 校验 `unreviewed` 与 `candidates` 为非负整数，`p0_in` 与 `p0_out` 为非负整数映射。
    - 读取 `membership.parquet` 后，实际统计 `actual_unreviewed`：若 `status == "final"` 且 `actual_unreviewed > 0`，或 `actual_unreviewed != details_raw["unreviewed"]`，坚决抛出 `SnapshotConflictError`。
    - 校验 parquet/jsonl 实际行数与 `outputs[i]["rows"]` 一致。
  - `src/aimx_recipes/sources/kaggle/snapshot.py`：
    - `verify_existing_snapshot` 接收 `expected_snapshot_id`，校验 manifest 中记录的 `snapshot_id` 必须相符。
    - 校验 manifest 中的 `counts` 对象，并对 `competitions.parquet`、`writeup_refs.parquet`、`writeups.parquet` 以及 `records/*.jsonl` 的实际行数与 manifest 中记录的各分项计数逐一进行核对，不匹配时坚决抛出 `SnapshotConflictError`。
  - `src/aimx_recipes/sources/kaggle/__init__.py`：
    - 调用 `verify_existing_snapshot` 时显式传入 `expected_snapshot_id=snap_id`。
  - `tests/integration/test_ingest_determinism.py`：
    - 新增单测 `test_tampered_membership_details_fails_conflict` 与 `test_tampered_snapshot_manifest_fails_conflict`。

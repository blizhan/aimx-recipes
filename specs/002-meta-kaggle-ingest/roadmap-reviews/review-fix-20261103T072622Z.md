### 1. S-01 (major) — DuckDB 会话仍默认 `.tmp`，可能溢出到 raw 边界外
- **审查问题**：
  - 复审探针 `actual_ingest_session_settings` 发现全量与复用流程中有 3 个会话未传入 `temp_dir`，DuckDB 返回 `temp_directory = .tmp`，相对于当前工作路径（cwd）。
  - 合成大排序探针 `default_session_synthetic_spill` 证明默认未设目录的会话会在 cwd 的 `.tmp/` 产生超过 46MB 的 native spill 文件，违反 Constitution Operational Boundaries 与 FR-001/FR-016。
  - 读取 parquet 损坏时报错抛出包含底层 DuckDB SQL 文本的异常。
- **改动**：
  - `src/aimx_recipes/sources/kaggle/snapshot.py`：
    - `open_session(threads=4, memory_limit="4GB", temp_dir=None)`：若 `temp_dir` 为 None，显式执行 `con.execute("SET temp_directory=''")`。当会话未显式指定目录时，禁用向当前工作目录创建 `.tmp` 溢出；若内存超限将抛出 `OutOfMemoryException`，杜绝任何外部隐式落盘。
    - `verify_existing_snapshot`：读取 parquet 校验逻辑内容时捕获底层异常，映射为脱敏固定的 `Corrupt or unreadable parquet file in snapshot: '{outp['path']}'`，不暴露底层 DuckDB SQL。
  - `src/aimx_recipes/sources/kaggle/__init__.py`：
    - `ingest()` 中复用分支（`verify_existing_snapshot`）与全量分支（`create_input_views`, `resolve_*`）均在 `raw_kaggle_dir` 内部创建唯一的 `session_temp` 临时目录（形如 `.tmp-verify-...` 和 `.tmp-resolve-...`），传入 `open_session(..., temp_dir=session_temp)`，并在 `finally` 块中通过 `shutil.rmtree(session_temp, ignore_errors=True)` 安全清理。
  - `src/aimx_recipes/sources/kaggle/membership.py`：
    - `verify_existing_membership`：读取 parquet 校验逻辑内容时，在 `final_mem_dir` 内部分配唯一的临时会话目录 `.tmp-memverify-...` 并传给 `open_session`，在 `finally` 块中清理；读取异常映射为脱敏固定的 `Corrupt or unreadable parquet file in membership: '{outp['path']}'`。
- **证据路径**：

### 2. S-03 (major) — 数值/通用异常泄漏输入片段，写失败仍 runtime_error
- **审查问题**：
  - 把 `Teams.csv` 中的 `CompetitionId` 替换为合成 `PRIVATE_BODY_MARKER` 时，CLI 抛出 `ValueError: invalid literal for int()...`，以 `code: runtime_error` 输出了 marker 字符串，且无 file/column/record_id/line。
  - membership 写入时注入 `OSError`，CLI 未映射为合同规定的稳定错误代码 `write_failed`，仍为 `runtime_error`。
  - 带 code 的异常直接透传包含底层 DuckDB SQL 文本的原文。
- **改动**：
  - `src/aimx_recipes/sources/kaggle/resolve.py`：
    - 引入 `safe_int(val, file, column, record_id, line)`，在整型转换失败时统一抛出 `InputError(code=ERR_CSV_MALFORMED, file=file, column=column, record_id=record_id, message=f"Invalid integer in column '{column}' of '{file}'")`。严格杜绝异常消息拼接用户输入字符串。
    - `resolve_writeup_references` 与 `resolve_competition_context`：SQL 中的排序使用 `ORDER BY TRY_CAST(...)` 代替 `CAST(...)`，避免 DuckDB 排序引擎直接抛出带输入字面的 ConversionException；在 Python 层由 `safe_int` 安全转换，精准定位 `file="Teams.csv"`, `column="CompetitionId"`, `record_id=team_leading_id`。
  - `src/aimx_recipes/cli/__init__.py`：
    - 增加对 `OSError` 的顶层捕获，映射为 `code: ERR_WRITE_FAILED`（`"write_failed"`），消息使用脱敏固定描述 `"File operation or disk write failed"`。
    - 通用未分类 `Exception`（`code == "runtime_error"`）统一脱敏为固定描述 `"An unexpected runtime error occurred during ingestion"`，绝不直接将未审查的底层异常字符串（含 SQL 或数据字面）输出到 JSON envelope 或 stderr。
- **证据路径**：

    - 当 `matched_tag_id is not None` 时，即使 `tag_name` 为空字符串或 None，也正常保留该 TagId（`tag_name` 存为 `""`），标签规则按 `TagId` 正常决策，不误报错误。
